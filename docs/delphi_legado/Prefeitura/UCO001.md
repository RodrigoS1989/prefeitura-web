# UCO001

Documentação para agentes de IA. Descreve o código; não substitui o fonte na hora de editar.

## Propósito

Correio de mensagens. Caption: "CO001 - Correio de Mensagens". Classe `TCO001`.

## Contexto de uso

Aberto pelo menu. O item não foi lido. Até esta revisão, o botão de responder dependia de o operador ser gestor e-SUS.

## Superfície pública

Saiu `procedure HabilitaComponentesGestor` e o dataset `tb_EsusGestores`.

## Fluxo principal

1. A tela abre o correio (`FormShow` / `FormClose` existem no dfm).
2. Não consulta mais se o operador está em `tb_EsusGestores` para habilitar `sbResponder`.

## Regras de negócio

- `sbResponder` deixou de ser habilitado pela existência do gestor em `tb_EsusGestores` (`HabilitaComponentesGestor` removido).
- A chamada que rodava quando `flCorreioAtivo` era falso também saiu.

## Dados

Removida a query `Select ISNULL(cd_Gestor, 0) as cd_Gestor From tb_EsusGestores Where dt_Exclusao is null and cd_Gestor = :cd_Gestor`, parâmetro `cd_Gestor` vindo de `Prefeitura_CorreioCodEmi`.

## Interface

- `CO001` — caption "CO001 - Correio de Mensagens".
- `sbResponder` era o botão condicionado ao gestor. O dfm perdeu o `TADOQuery tb_EsusGestores`.

## Dependências

`Prefeitura_Correio` continua na tela. `UModGeral` não expõe mais `tb_EsusGestores`.

## Cuidados ao alterar

Fonte Windows-1252. Recolocar a query sem a tabela no data module quebra a abertura do correio.

## Alteração na revisão

Removidos o dataset, `HabilitaComponentesGestor` e a chamada na abertura. O dfm perdeu o query.

## Limites

O fluxo do correio (enviar, ler, responder) não foi lido. A unit tem cerca de 283 linhas; o diff é só a remoção do gestor.
