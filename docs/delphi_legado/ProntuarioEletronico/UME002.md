# UME002

Documentação para agentes de IA. Descreve o código; não substitui o fonte na hora de editar.

## Propósito

Atendimentos do prontuário. Caption: "ME002 - Atendimentos". Classe `TME002`. Ao concluir o atendimento, envia para a API e-SUS as fichas geradas (FAI, FAP, FAO, FAD).

## Contexto de uso

Tela principal do atendimento. O chamador não foi lido. O envio usa `TEsus.NovoControlador` depois do commit, porque a API abre outra conexão.

## Superfície pública

- `procedure EnviarFichaApiPorAtendimento(ANumAtendimento: Integer; ATipoFicha: TEsusTipoFicha)`
- `destructor Destroy` — declarado nesta revisão. O corpo não foi lido.

## Fluxo principal

1. O atendimento marca quais fichas gerar (`LEnviarFAI`, `LEnviarFAP`, `LEnviarFAO`, `LEnviarFAD`).
2. Depois do commit, para cada flag verdadeiro chama `EnviarFichaApiPorAtendimento` com `DadosPaciente.CodigoAtend` e o tipo.
3. O método busca o maior código da ficha do atendimento (`TOP 1`, não excluída) e chama `EnviarFichaApi`.

## Regras de negócio

- A ficha considerada é a de maior código do atendimento, com `ISNULL(fl_Excluido, 0) = 0`.
- Se não houver ficha, não envia.
- O comentário no fonte diz que `EnviarFichaApi` usa `conFabrica` (outra conexão) e não enxerga ficha ainda não confirmada na transação do módulo. Por isso o envio fica depois do commit.
- Combinações vistas no diff: um ramo liga FAI, FAP e FAO; outro liga FAD; outro liga FAI e FAO; outro liga FAD. O critério de cada ramo (tipo de atendimento) não foi lido.

## Dados

Tabela e campo vêm de `ATipoFicha.GetTable` e `GetFieldCode`. Filtro `nr_Atendimento`. Tipos: `etfFAI`, `etfFAP`, `etfFAO`, `etfFAD`.

## Interface

- `ME002` — caption "ME002 - Atendimentos". O dfm não mudou de conteúdo.

## Dependências

`Shared.Esus`.

## Cuidados ao alterar

Fonte Windows-1252. A unit tem cerca de 33802 linhas. Mover `EnviarFichaApi` para dentro da transação faz a API não achar a ficha. A nota de versão `2.26.0.49` cita correção de FAD inconsistente gerada por este prontuário.

## Alteração na revisão

Método `EnviarFichaApiPorAtendimento`, flags de envio e a chamada depois do commit. Declarado `destructor Destroy`.

## Limites

Não foi lido qual tipo de atendimento liga cada flag. O corpo do `Destroy` não foi lido.
